## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
R3 does not happen at all. An agent leaves plan mode and nothing asks whether the plan makes an undocumented decision — the cheapest moment to notice one, and the only moment where the answer can still shape the implementation instead of justifying it.

**Cause.** `hooks/manifest.json` sets `"id": "plan-exit", "command": "plan-exit"` while its sibling sets `"id": "pr-create", "command": "pre-tool-use"`. `run-hook.cmd` passes the command verbatim as `--event`, `normalize()` lets that argument win over the payload, and `re.sub(r'[^a-z]','','plan-exit')` is `planexit`, which is absent from `EVENT_ALIASES` — so `evaluate()` falls through to `return "", "noop"`. Measured: `--event plan-exit` returns 0 bytes; the identical payload with `--event pre-tool-use` returns the full injection.

**Why no test caught it.** `tests/test_adr_plan_exit_hook.py::_envelope` calls `core.normalize(payload, client, None)` with event `None`, so the payload wins and the failing step is never exercised. Twenty-four tests pass over a dead path, and the CHANGELOG credits the feature, so nobody is looking.

No ADR needed: this is the fourth instance of a pattern ADR-004 already governs.

Reported by a subagent; **verify by reproduction before fixing**, since it is going into a release.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Reproduced first, as the task required: one `ExitPlanMode` payload returned **0 bytes** under `--event plan-exit` and **1900 bytes** under `--event pre-tool-use`.

Fixed on the manifest side rather than in `EVENT_ALIASES`. The alias table maps *client protocol event names*; adding `planexit` there would have made it carry two vocabularies at once. `"command": "pre-tool-use"` is what the `pr-create` entry already does with its `Bash` matcher, and `evaluate()` already dispatches plan exit on `envelope.event == "PreToolUse"` and `tool in PLAN_EXIT_TOOLS`, so the branch was reachable all along — nothing but the command id kept it dark.

`tests/test_adr_hook_dispatch_matrix.py` drives every manifest event through the real process on every client that declares it, using an ADR set generated by `bin/adr-index` rather than a hand-written index. The hand-written index was tried first and would have passed for the wrong reason: `_query` asks with `strict_index=True`, so an index with no markdown behind it is stale and every event fails open to noop.

AC#4 is not done here: `docs/client-support.md` is regenerated as a whole in TASK-115, which now has the true state to regenerate from.

Shipped in v0.44.1.
